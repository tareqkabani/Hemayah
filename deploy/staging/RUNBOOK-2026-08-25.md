# RUNBOOK — نشرُ معالجة التدقيق الأمنيّ إلى التجريبية (٢٥ أغسطس ٢٠٢٦)

يرفع هذا الدليلُ إلى خوادم التجريبية الداخليّة كلَّ ما دُمج في `main` من معالجة
التدقيق: **٥ مهاجرات · إعداد المصادقة · ترقية Next 15 · ترويسات الوكيل**.

> **قبل البدء:** اتّصل بالـVPN. جهّز `DB_URL` وكلمةَ سرّ القاعدة ووصولَ Portainer.
> نفّذ الخطوات **بالترتيب** — القاعدة أوّلاً ثمّ الشيفرة (الشيفرةُ الجديدة تنادي
> ما تُنشئه المهاجرات). كلُّ مهاجرةٍ idempotent، فإعادةُ التشغيل آمنة.

## أ) المهاجرات الخمس الجديدة → قاعدة التجريبية

`oneshot` يُطبّق ما بعد `FROM_VERSION` ويُسجّل كلَّ مهاجرةٍ في `schema_migrations`.

```bash
# 1) اعرف حالة التجريبية الفعليّة (آخر مهاجرة مُسجّلة)
psql 'postgresql://postgres:PASS@DB_HOST:55322/postgres' \
  -c "select max(version) from supabase_migrations.schema_migrations;"
```

اضبط `FROM_VERSION` على القيمة الظاهرة (مثلاً `20260813000008`)، ثمّ:

```bash
cd <جذر المستودع على جهاز الفاحص>
git checkout main && git pull            # يجب أن يحمل إصلاحات الأمن المدموجة

# 2) عرضٌ بلا تنفيذ — يجب أن يُظهر الخمس 20260825… فقط
FROM_VERSION=20260813000008 \
DB_URL='postgresql://postgres:PASS@DB_HOST:55322/postgres' \
  ./deploy/staging/oneshot-2026-08-10.sh --dry-run

# 3) التنفيذ
FROM_VERSION=20260813000008 \
DB_URL='postgresql://postgres:PASS@DB_HOST:55322/postgres' \
  ./deploy/staging/oneshot-2026-08-10.sh
```

**تحقّق (يجب أن تكون كلُّها صفراً/واحداً كما يلي):**

```bash
psql "$DB_URL" -c "
  select 'rc_insert' k, count(*) v from pg_policies where tablename='risk_classifications' and policyname='rc_insert'
  union all select 'subjects_restrictive', count(*) from pg_policies where tablename='subjects' and permissive='RESTRICTIVE'
  union all select 'anon_secdef_exec', count(*) from pg_proc p where p.pronamespace='public'::regnamespace and p.prosecdef and has_function_privilege('anon',p.oid,'EXECUTE')
  union all select 'stray_tables', count(*) from pg_class c join pg_namespace n on n.oid=c.relnamespace where n.nspname='public' and c.relkind='r' and c.relname in ('e1','officer','studier');"
# المتوقّع: rc_insert=0 · subjects_restrictive=1 · anon_secdef_exec=0 · stray_tables=0
```

## ب) إعداد المصادقة (إقفال التسجيل + كلمة المرور) → إعادة تشغيل Supabase

تغييرات `config.toml` ليست مهاجرات؛ يقرؤها GoTrue عند الإقلاع.

```bash
# على مضيف قاعدة التجريبية (بعد git pull main):
supabase stop && supabase start          # يحفظ الحجم، يعيد قراءة config.toml
```

**تحقّق:**

```bash
docker exec supabase_auth_<PROJECT> env | grep -E "DISABLE_SIGNUP|EXTERNAL_EMAIL_ENABLED"
# المتوقّع: GOTRUE_DISABLE_SIGNUP=true · GOTRUE_EXTERNAL_EMAIL_ENABLED=true
```

> ⚠️ الأهمّ: **يبقى `EXTERNAL_EMAIL_ENABLED=true`** — وإلّا انكسر دخولُ الجسر.
> إقفالُ التسجيل من `[auth]` وحده (لا `[auth.email]`). إن رأيتَ «Email logins
> disabled» فراجع أنّ `[auth.email].enable_signup = true`.

## ج) الواجهات والـAPI → إعادة نشر Portainer

الحاويتان تبنيان من الشيفرة (`frontend.Dockerfile` على `node:22-alpine`).
في Portainer، لكلّ stack: **Pull and redeploy** (يسحب `main` ويعيد البناء).

- `frontend.stack.yml` — يبني البوابات على Next 15 + يعيد بناء الوكيل بترويساته.
- `api.stack.yml` — الآن فيه `deploy: replicas: 1` (HMY-13) — أبقِ مثيلاً واحداً.

> ⚠️ **راقب بناء sharp:** Next 15 يجرّ `sharp` للصور. الموافقةُ في
> `pnpm-workspace.yaml` (مدموجة). إن فشل البناء على sharp في alpine، أضِف في
> `frontend.Dockerfile` قبل `pnpm build`:  `RUN apk add --no-cache vips`.

> ℹ️ **الوكيل والشهادة (HMY-14):** إن لم تضبط `APP_ENV=production` يبقى الوكيل
> يولّد شهادةً ذاتيّةَ التوقيع (سلوك التجريبية الحاليّ — لا ينكسر). لتفعيل
> **رفضِ الإقلاع بلا شهادةٍ حقيقيّة** أضِف في env الوكيل: `APP_ENV=production`
> **مع** `TLS_CERT_B64`/`TLS_KEY_B64`.

## د) التحقّق النهائيّ (من متصفّحٍ على الشبكة)

```bash
# 1) التسجيل الذاتيّ مقفل (HMY-04)
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  "https://PUBLIC_HOST/supabase/auth/v1/signup" \
  -H "apikey: ANON_KEY" -H "Content-Type: application/json" \
  -d '{"email":"x@example.com","password":"Hunter2xxxxx"}'          # المتوقّع: 422

# 2) ترويسات الأمان حاضرة (HMY-08)
curl -sI "https://PUBLIC_HOST/" | grep -iE "strict-transport|x-frame|x-content-type|referrer-policy"
```

- الدخولُ عبر نفاذ (الجسر) يعمل.
- بوّابةٌ أو اثنتان تفتحان وتعرضان البيانات (‏Next 15 لم يكسر شيئاً).
- مُدقِّق Supabase (‏Studio ← Advisors): صفر ERROR؛ تبقى تحذيرات `0029/0008`
  المقبولة الموثَّقة (‏`supabase/LINTER-ADVISORIES.md`).

## هـ) التراجع (إن لزم)

- **المهاجرات** idempotent ولا تحذف بيانات تشغيل؛ لا تراجعَ مطلوبٌ عادةً.
  (‏`20260825000003` يحذف الجداول الشاردة فقط — نُسخُ id، لا بيانات أصليّة.)
- **الشيفرة:** في Portainer أعِد نشرَ وسمِ الإصدار السابق (`git` SHA السابق).
- **المصادقة:** لإرجاع التسجيل مؤقّتاً: `enable_signup = true` في `[auth]` ثمّ
  `supabase stop && supabase start`.
